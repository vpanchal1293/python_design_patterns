A class should have only one reason to change, meaning it should have only one responsibility or job.
| Concept       | Description                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| **Principle** | **Single Responsibility Principle (SRP)**                                                               |
| **Problem**   | A class or module handles multiple responsibilities, causing changes in one area to affect others.      |
| **Solution**  | Each class should have **only one reason to change**, meaning it should handle a single responsibility. |
| **Benefit**   | Code becomes easier to maintain, understand, and test — changes are isolated to specific areas.         |
